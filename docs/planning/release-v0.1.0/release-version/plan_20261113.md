## Phases

### Phase 1: Version and metadata

- **Steps:** failing tests (pyproject 0.1.0, `--version` output); bump `pyproject.toml`, `uv lock`,
  `uv sync`; green.
- **Validation:** `uv run pytest tests/test_release.py -k version`; `uv run tenon --version`.
- **Commit:** `chore(release): bump to 0.1.0`

### Phase 2: Changelog, checklist and the release-check script

- **Steps:** failing tests (the changelog heading, the script exists/executable); write
  `CHANGELOG.md`, `docs/RELEASE.md`, `scripts/release_check.sh`; run the script; green; full suite.
- **Validation:** `uv run pytest tests/test_release.py`; `bash scripts/release_check.sh`.
- **Commit:** `docs: add the v0.1.0 changelog and release checklist`

## Testing strategy

- Static version/changelog/script checks; the installed `--version`; the script is run manually (it
  builds/installs, so not in pytest). One test per AC, cited `# Spec AC<n>`.

## Environment & secrets

- None; the script uses a temporary venv and no network beyond the local wheel/uv sync.
