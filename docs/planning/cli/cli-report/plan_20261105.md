## Phase 1: Exit codes

- **Goal:** the honest mapping before any text.
- **Prerequisites:** `cli-config`; shipped `LocateResult`, `ProofResult`, `PrResult`.
- **Files:** `tests/cli/test_report.py` (new), `src/tenon/cli/report.py` (new).
- **Steps:**
  1. Write failing tests for `check_exit`: certain → 1, ambiguous → 1, `NO_SITES` → 0,
     `UNSUPPORTED_CHANGE_KIND` → 0, `NO_SDK_IMPORT` → 1, `OPERATION_NOT_MAPPED` → 1, empty → 0.
  2. Write failing tests for `fix_exit`: zero changes → 0; a passed proof with no PR → 0; UNVERIFIED
     under `TESTS_PASSED` → 1; UNVERIFIED under `UNVERIFIED` → 0; a refused PR → 1.
  3. Run — red.
  4. Implement `FixResult` and the two exit functions.
  5. Run — green.
- **Validation:** `uv run pytest tests/cli/test_report.py -k exit`.
- **Commit:** `feat(cli): map check and fix results to exit codes`

## Testing strategy

- Build `Change`, `LocateResult`, `Proposal`, `ProofResult` and `PrResult` directly; no repo, no
  subprocess except the hash-seed check.
- One test per acceptance criterion, cited as `# Spec AC<n>`.
- Text goldens are exact strings for one small report; other tests assert lines.

## Environment & secrets

- None. No network, no `gh`, no git.

## Edge cases & error handling

- `ProofResult` with `baseline`/`after` `None` renders `not run`; a timeout renders `timed out`.
- `PrResult` with `status REFUSED` renders the refusal and the detail; `OPENED` renders the URL.
- A `LocateResult` with a reason and no sites renders the reason, not an empty block.
- Summary counts are integers; zero results produce zero counts.
