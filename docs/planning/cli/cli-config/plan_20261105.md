## Phase 1: `CliConfig` and defaults

- **Goal:** one frozen config object with the shipped defaults.
- **Prerequisites:** none.
- **Files:** `tests/cli/__init__.py` (new), `tests/cli/test_config.py` (new),
  `src/tenon/cli/config.py` (new), `src/tenon/cli/__init__.py` (new).
- **Steps:**
  1. Write failing tests for a minimal `tenon.toml` (`[locate] sdk_package = "stripe"`): the loaded
     `CliConfig` has the shipped `LocateConfig`, `command == ()`, `require is ProofLevel.TESTS_PASSED`,
     `breaking_only is False`.
  2. Write a failing test for a full file: `[locate.operations]`, `[locate.fields]`, `[tenon]`
     `command = ["python", "-m", "pytest", "-q"]`, `require = "UNVERIFIED"`, `breaking_only = true`.
  3. Run — red (module missing).
  4. Implement the dataclass and the loader; put test TOML files under `tmp_path`.
  5. Run — green.
- **Validation:** `uv run pytest tests/cli/test_config.py -k "defaults or full"`.
- **Commit:** `feat(cli): load the CLI config with shipped defaults`

## Phase 2: Validation with named errors

- **Goal:** a malformed config never becomes a traceback.
- **Prerequisites:** Phase 1.
- **Files:** `src/tenon/cli/config.py`, `tests/cli/test_config.py`.
- **Steps:**
  1. Write failing tests for: missing `[locate]`, missing `sdk_package`, `command` as a bare string,
     an empty command element, non-bool `breaking_only`, unknown `require` (the message names T7).
     Each raises `ValueError` and names the key/path.
  2. Run — red.
  3. Implement the checks; reuse `LocateConfig` for its own validation.
  4. Run — green.
- **Validation:** `uv run pytest tests/cli/test_config.py -k valid`.
- **Commit:** `feat(cli): name malformed CLI config keys`

## Phase 3: Flag overrides and `shlex`

- **Goal:** flags win over the file, with one controlled string split.
- **Prerequisites:** Phase 2.
- **Files:** `src/tenon/cli/config.py`, `tests/cli/test_config.py`.
- **Steps:**
  1. Write failing tests for `--sdk-package`, `--operation`, `--field`, `--check`, `--require`,
     `--breaking-only`/`--no-breaking-only` over a loaded config; operations/fields merge and win;
     `--check "python -m pytest -q"` becomes `("python", "-m", "pytest", "-q")`.
  2. Write failing tests for `--operation missing-equals`, `--operation =x`, `--check ""`.
  3. Run — red.
  4. Implement `overrides(...)` with a `KEY=VALUE` splitter and `shlex.split`.
  5. Run — green.
- **Validation:** `uv run pytest tests/cli/test_config.py -k "override or shlex"`.
- **Commit:** `feat(cli): apply flag overrides over tenon.toml`

## Phase 4: Config path and a missing SDK package

- **Goal:** find the repo config or fall back cleanly.
- **Prerequisites:** Phase 3.
- **Files:** `src/tenon/cli/config.py`, `tests/cli/test_config.py`.
- **Steps:**
  1. Write failing tests: an explicit path wins; `<repo>/tenon.toml` is found; an absent file returns
     `None`; a `None` config with no `--sdk-package` raises `ValueError`.
  2. Run — red.
  3. Implement `resolve_config_path` and the empty-config path.
  4. Run — green; run the whole suite.
- **Validation:** `uv run pytest` (745 + new tests).
- **Commit:** `feat(cli): resolve the repo config and require an SDK package`

## Testing strategy

- Unit tests only; `tmp_path` TOML files; no pipeline imports or calls.
- One test per acceptance criterion, cited as `# Spec AC<n>`.
- The config loader is the only file read; no repo scan.

## Environment & secrets

- None. No network, no `gh`, no git.

## Edge cases & error handling

- `tomllib.TOMLDecodeError` is wrapped with the file path and a stable prefix.
- A missing file is `None` (caller fallback), not a crash.
- Unknown `[tenon]` keys are ignored; future keys do not break this CLI.
- A future `--require` value names T7 rather than silently downgrading.
