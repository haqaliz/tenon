## Testing strategy

- `main(...)` unit tests for exits and reports; one subprocess test for `python -m tenon`.
- The fixture repo is a temp copy, so tests never write the shared fixture.
- `fix --open-pr` uses a fake `write_pr` and remote; T5's real writer is tested in `tests/pr/`.
- One test per acceptance criterion, cited as `# Spec AC<n>`; JSON goldens use exact keys.

## Environment & secrets

- `git` is not needed for `check` or local `fix`; the fake remote path avoids it for `--open-pr`.
- No `gh`, no network, no token.
- The check command uses the running interpreter and a one-line import, as in `tests/prove/`.

## Edge cases & error handling

- `argparse` help/usage exits are caught and returned as ints; help is 0, usage is 2.
- A missing repo, spec or config is exit 2 with a named message.
- A spec refusal is exit 2 with `code`, `pointer`, `message`; `--json` puts the error object on
  stdout.
- An unexpected exception is exit 1 with an `internal` envelope; the traceback never reaches stdout.
- `--open-pr` with multiple proposals runs each; the report names each PR/refusal, and the exit is 1
  if any failed.
