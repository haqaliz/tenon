## Phase 1: Evidence bindings

- **Goal:** a `let` binds a receiver type from construction/annotation/factory.
- **Prerequisites:** `receiver-config`.
- **Files:** `rust_scan.py`, tests.
- **Steps:**
  1. Write failing tests: `Client::new`, `crate::Client::new`, `Client::default`; `let c: Client`
     and `let c: crate::Client`; a `receivers` key for `make_client` and `crate::make_client`; an
     unmapped factory is not evidence; a rebinding replaces/clears.
  2. Run — red; implement the `let` evidence; green.
- **Validation:** `uv run pytest tests/locate/test_rust_scan.py -k "receiver or evidence"`.
- **Commit:** `feat(locate): bind Rust receiver types`

## Phase 2: Receiver chains and policy

- **Goal:** a method/field chain on a bound receiver is rooted and certain.
- **Prerequisites:** Phase 1.
- **Files:** `rust_scan.py`, `rust_locate.py`, tests.
- **Steps:**
  1. Write failing tests: `client.charges().create(...)` -> `(Client,charges,create)` plus the
     intermediate `(Client,charges)`; a field access -> `(Client,field)`; an untracked chain not
     certain; a `locate_rust` operation/component case with a mapped chain.
  2. Run — red; implement `_receiver` and the method-call hits; green; full suite.
- **Validation:** `uv run pytest tests/locate/test_rust_*.py`; full suite.
- **Commit:** `feat(locate): locate Rust receiver chains`

## Edge cases & error handling

- A field access chain is followed only on a tracked receiver.
- A constructor other than `new`/`default` needs a mapping.
- Rebinding clears without evidence.
