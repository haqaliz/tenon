## Phase 1: Stages, levels, rank and causes

- **Goal:** the closed vocabularies before the runner uses them.
- **Prerequisites:** none.
- **Files:** `src/tenon/prove/result.py`, `tests/prove/test_result.py`.
- **Steps:**
  1. Write failing tests: `ProofStage` exactly `BUILD, CHARACTERIZE, REPLAY, TESTS`; `ProofLevel`
     exactly `TESTS_PASSED, CHARACTERIZED, REPLAYED, TYPES_BUILD_ONLY, UNVERIFIED`; `PROOF_RANK`
     values 4..0; `proof_rank` coerces a string and raises on an unknown; `ProofCause` is the
     fourteen-value closed set.
  2. Update the old pins: `test_proof_level_values_are_the_closed_two` becomes five;
     `test_proof_cause_values_are_the_closed_seven` becomes fourteen.
  3. Run — red.
  4. Implement the enums/rank/causes. Keep the existing names.
  5. Run — green.
- **Validation:** `uv run pytest tests/prove/test_result.py -k "level or rank or cause or stage"`.
- **Commit:** `feat(prove): add the five proof levels and stages`

## Phase 2: `CheckResult.stage`

- **Goal:** every check names its stage, with the old constructor unchanged.
- **Prerequisites:** Phase 1.
- **Files:** `src/tenon/prove/result.py`, `tests/prove/test_result.py`.
- **Steps:**
  1. Write failing tests: a check without `stage` is `TESTS`; a string coerces; an unknown raises;
     `to_dict()` has the old keys plus `stage`.
  2. Update the dict-shape test in `tests/prove/test_result.py` and the CLI/PR tests that compare a
     `CheckResult.to_dict()` exactly (search for the old key set).
  3. Run — red; implement; green.
- **Validation:** `uv run pytest tests/prove/test_result.py -k stage` and the full suite for the
  dict-shape pins.
- **Commit:** `feat(prove): record the stage on every check`

## Phase 3: `ProofResult.checks` and the level invariants

- **Goal:** one result carries every stage that ran, without breaking the old constructors.
- **Prerequisites:** Phase 2.
- **Files:** `src/tenon/prove/result.py`, `tests/prove/test_result.py`.
- **Steps:**
  1. Write failing tests: `checks` defaults to `()`; a sequence coerces; `to_dict()` has `checks`;
     a green `TYPES_BUILD_ONLY`/`REPLAYED`/`CHARACTERIZED`/`TESTS_PASSED` with the matching green after
     check constructs; a missing/mismatched/red after raises; a new level without `checks` raises;
     the old `TESTS_PASSED` and `UNVERIFIED` constructors still work; the JSON is byte-stable.
  2. Run — red.
  3. Implement `checks`, the level→stage map, the invariant extension and the JSON.
  4. Run — green; full suite (the `to_dict` key-set test updates).
- **Validation:** `uv run pytest tests/prove/test_result.py`.
- **Commit:** `feat(prove): carry every stage check on the proof result`

## Edge cases & error handling

- A green level with `checks` but a red/mismatched after raises at construction.
- A new level with no `checks` raises; the runner always populates them.
- `UNVERIFIED` keeps the T4 rule (a cause; `patch_applied` may be true after a failed after-check).
- The enum order is presentational; only `PROOF_RANK` compares.
