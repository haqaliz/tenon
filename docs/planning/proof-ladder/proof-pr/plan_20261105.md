## Phase 1: `BELOW_REQUIRED_LEVEL`

- **Goal:** a named refusal for a weak-but-not-unverified result.
- **Prerequisites:** `proof-result`.
- **Files:** `src/tenon/pr/result.py`, `tests/pr/test_result.py`.
- **Steps:** write a failing test for the new value, update the pinned refusal list, implement, green.
- **Validation:** `uv run pytest tests/pr/test_result.py -k refusal`.
- **Commit:** `feat(pr): name the below-required refusal`

## Phase 2: The required-level gate

- **Goal:** normal at/above, refusal below, draft only with opt-in.
- **Prerequisites:** Phase 1; `proof-result`.
- **Files:** `src/tenon/pr/write.py`, `tests/pr/test_write.py`.
- **Steps:**
  1. Write failing tests: `TYPES_BUILD_ONLY` + `required=TESTS_PASSED` + no opt-in →
     `BELOW_REQUIRED_LEVEL`, no push/PR, detail names both; with `allow_below_required=True` →
     `create_pr(draft=True)`; `TYPES_BUILD_ONLY` + `required=TYPES_BUILD_ONLY` → normal;
     `TESTS_PASSED` + `required=TYPES_BUILD_ONLY` → normal; `UNVERIFIED` + no opt-in →
     `UNVERIFIED_NOT_ALLOWED`; `allow_unverified=True` is the alias; `UNVERIFIED` +
     `required=UNVERIFIED` → draft.
  2. Run — red.
  3. Add `required`/`allow_below_required` (and the alias), compute `below`/`draft`, map the
     refusal; the existing preconditions and clone/push/PR stay.
  4. Run — green.
- **Validation:** `uv run pytest tests/pr/test_write.py -k "required or below or unverified"`.
- **Commit:** `feat(pr): gate the PR on the required proof level`

## Phase 3: Level sentences and paragraphs

- **Goal:** the body says what each new level actually proved.
- **Prerequisites:** Phase 2.
- **Files:** `src/tenon/pr/render.py`, `tests/pr/test_render.py`.
- **Steps:**
  1. Write failing tests for `CHARACTERIZED`, `REPLAYED`, `TYPES_BUILD_ONLY`: the title carries the
     level; the body has the fixed sentence, the command, and the paragraph; no weak level is called
     verified; `TESTS_PASSED`/`UNVERIFIED` text is unchanged.
  2. Build `ProofResult`s with the matching `checks` (the proof-result invariant requires them).
  3. Run — red; add the map entries; green.
- **Validation:** `uv run pytest tests/pr/test_render.py`.
- **Commit:** `feat(pr): state the new proof levels honestly`

## Edge cases & error handling

- A `required` level with no `checks` is impossible for the new levels; the proof-result invariant
  rejects it.
- `UNVERIFIED` is always a draft, even when required.
- `allow_unverified` is an alias; the CLI may pass either.
- The below-required refusal happens before any clone/push/PR.
