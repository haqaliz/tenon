## Phase 2: One-stage `prove_plan`

- **Goal:** a build/characterize/replay/tests stage runs baseline-first and yields its level.
- **Prerequisites:** Phase 1.
- **Files:** `src/tenon/prove/run.py`, `tests/prove/test_plan.py`.
- **Steps:**
  1. Write failing tests on a fixture repo: a green build only → `TYPES_BUILD_ONLY`; a green
     characterize only → `CHARACTERIZED`; a green replay only → `REPLAYED`; a green tests only →
     `TESTS_PASSED`; each `checks` record has the right stage; `patch_applied` true.
  2. Write failing tests: an empty plan → `NO_PROOF_COMMAND`; a red baseline → the stage's
     `*_FAILED_BEFORE` with no apply; a red after → the stage's `*_FAILED_AFTER`.
  3. Run — red.
  4. Implement the single-stage runner, cause mapping and the primary check.
  5. Run — green.
- **Validation:** `uv run pytest tests/prove/test_plan.py -k "single or stage"`.
- **Commit:** `feat(prove): run a single proof stage`

## Phase 3: Multi-stage baselines, apply once and fail closed

- **Goal:** the honest ladder: all baselines, one apply, all afters, strongest green or UNVERIFIED.
- **Prerequisites:** Phase 2.
- **Files:** `src/tenon/prove/run.py`, `tests/prove/test_plan.py`.
- **Steps:**
  1. Write failing tests: build+characterize+replay+tests all green → `TESTS_PASSED`, eight check
     records in `BUILD, CHARACTERIZE, REPLAY, TESTS` order; green build + red tests →
     `UNVERIFIED / TESTS_FAILED_AFTER` with the build pass in `checks`; a red build baseline stops
     before apply; a red replay baseline → `REPLAY_FAILED_BEFORE`; a garbage diff →
     `PATCH_DID_NOT_APPLY` with the baselines recorded; the diff applies once (assert the copy's
     file content once).
  2. Write failing tests: a stage timeout → `CHECK_TIMED_OUT` with the stage; the source tree is
     unchanged; the temp copy is removed on every path.
  3. Run — red.
  4. Implement the baseline loop, the single apply, the after loop, the strongest-level selection and
     the primary `baseline`/`after` selection.
  5. Run — green.
- **Validation:** `uv run pytest tests/prove/test_plan.py`.
- **Commit:** `feat(prove): run the proof ladder fail-closed`

## Edge cases & error handling

- A baseline failure stops before apply; the after list is empty.
- An apply failure keeps every baseline in `checks`.
- A red stronger stage is `UNVERIFIED`, never a weaker level.
- The primary `baseline`/`after` is the tests check if configured, else the strongest stage's.
- A timeout in one stage stops the run; the check records the stage.
