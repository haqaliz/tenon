## Testing strategy

- Fixture commands are `sys.executable -c` scripts; no Node, network or gh.
- `fix --open-pr` uses a fake `write_pr`/remote; the real writer is tested in `tests/pr`.
- One test per acceptance criterion, cited as `# Spec AC<n>`.
- JSON determinism across hash seeds for a build-only fix report.

## Edge cases & error handling

- A configured stage that is not reachable with the current language still runs the same command;
  the user chose it.
- A build-only result with a tests requirement exits 1; the text says why.
- An empty plan is `NO_PROOF_COMMAND`, exit 1; an empty `--check` is a config error.
- The `--allow-unverified` alias maps to `allow_below_required`.
