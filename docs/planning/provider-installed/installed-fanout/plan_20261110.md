## Testing strategy

- Fake `list_installation_repos`/`clone_repo` in `tenon.cli.main`; local `proof-basic` copies as
  clone targets; a fake `write_pr`/remote; no network/gh.
- One test per acceptance criterion, cited as `# Spec AC<n>`.

## Environment & secrets

- None; app flags/env are set to test values; the key file is a temp PEM.

## Edge cases & error handling

- A clone error is per-repo; a token/list error is global (exit 2).
- The report key is `owner/name`, never the temp path.
- The token is minted once and never printed.
- The single-repo and `--repos` paths are unchanged.
