## Testing strategy

- `check --language ts` uses the real locator on a committed fixture.
- `fix --language ts` monkeypatches `prove` to return a `ProofResult`; T4's proof is unchanged and
  tested in `tests/prove/`. No Node in the suite.
- One test per acceptance criterion, cited as `# Spec AC<n>`.
- JSON determinism across hash seeds for a TS check report.

## Environment & secrets

- None. No network, no Node, no `gh`.

## Edge cases & error handling

- `--language ts` with a `tenon.toml` `sdk_package` that is Python-shaped: the npm validator may
  accept `foo.bar` (dots are valid npm); the user can override. A genuinely invalid name is exit 2.
- A missing config and `--language ts` without `--sdk-package` is exit 2.
- The `CliConfig` union is internal; the report and `Site` contracts are unchanged.
