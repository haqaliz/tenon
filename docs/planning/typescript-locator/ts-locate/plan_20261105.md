## Phase 1: `TsLocateConfig` and the `QueryConfig` protocol

- **Goal:** a TS config that `derive` accepts without changing Python behaviour.
- **Prerequisites:** `ts-scan` (not required yet for the config tests).
- **Files:** `src/tenon/locate/ts_config.py`, `src/tenon/locate/query.py`,
  `src/tenon/locate/resolve.py`, `src/tenon/locate/__init__.py`, `tests/locate/test_ts_config.py`.
- **Steps:**
  1. Write failing tests: `TsLocateConfig(sdk_package="stripe")` and `"@scope/pkg"` construct;
     empty/whitespace/path-like/`@`-malformed names raise `ValueError`; mappings are immutable.
  2. Write a failing test that `derive(change, TsLocateConfig(...))` returns the same `Query` as the
     Python config for the same mappings.
  3. Run — red.
  4. Add the `QueryConfig` Protocol and change only the type hints in `query.py`/`resolve.py`; add
     `TsLocateConfig`.
  5. Run — green; the full suite proves Python is unchanged.
- **Validation:** `uv run pytest tests/locate/test_ts_config.py tests/locate/test_query.py`.
- **Commit:** `feat(locate): add the TypeScript locate config`

## Testing strategy

- Fixtures are read-only; no Node, no network.
- One test per acceptance criterion, cited as `# Spec AC<n>`.
- The decoy test asserts both no certain site and an unrooted/absent candidate as appropriate.

## Environment & secrets

- None. tree-sitter is already installed by `ts-scan`.

## Edge cases & error handling

- A config with a Python package name under the TS type is allowed by the permissive npm validator?
  No: `foo.bar` is a valid npm-ish name (dots allowed); the user chose the config. A path-like
  `foo/bar` is rejected except `@scope/name`.
- A `Change` with no operation scope uses the component rules; the shared resolver decides.
- An empty repository returns `NO_SDK_IMPORT`, not an exception.
