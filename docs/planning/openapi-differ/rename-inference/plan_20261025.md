## Prerequisites

## Phases

### Phase 1: Unambiguous pairing (TDD)

- **Files:** `src/tenon/detect/rename.py`, `tests/detect/test_rename.py`, fixtures.
- **Steps:**
  1. Tests: one removed + one added property of the same type → one `renamed`, zero removed/added.
  2. Test: two added candidates for one removed → no rename, 3 records retained, all `certain`.
  3. Test: same name different type → no rename.
  4. Implement `infer_renames(changes: list[Change]) -> list[Change]`: group by
     `(parent_pointer, family)`, build the removed→added candidate map, accept a pair only when it is
     unique in both directions, replace with a `renamed` record (`breaking=True`,
     `confidence="inferred"`).
- **Validation:** `uv run pytest tests/detect/test_rename.py`
- **Commit:** `feat(detect): infer unambiguous renames and never guess`

### Phase 2: Endpoint renames + wiring (TDD)

- **Files:** `src/tenon/detect/rename.py`, `src/tenon/detect/diff.py`, `tests/detect/test_rename.py`
- **Steps:**
  1. Tests: `/v1/users` → `/v2/users` same method is a rename; different method is not; a two-way
     swap (2 removed, 2 added, same shape) yields zero renames.
  2. Path templates normalised to `{}` placeholders before shape comparison; differing parameter
     count refuses the pair.
  3. `diff()` runs `infer_renames` as its final step so the public API stays `diff(old, new)`.
  4. Assert `to_json()` still byte-stable after the pass.
- **Validation:** `uv run pytest`
- **Commit:** `feat(detect): detect endpoint renames and run inference inside diff`

## Testing strategy

- Exhaustive small-table tests: for each (removed, added) shape combination assert rename or no
  rename. This is the aspect where a wrong guess is a product-level lie, so the negative cases
  matter more than the positive ones.
- Property: `infer_renames` is idempotent — running it twice changes nothing.

## Edge cases

- Two identical removed property names under the same parent cannot happen (dict keys are unique);
  ambiguity therefore comes from shape collisions across *different* names, which is exactly the
  case the rule refuses.
- `confidence` on a `renamed` record is always `inferred`; a `certain` rename must be impossible by
  construction (no explicit-hint path in this card).
- Endpoint rename to/from a path with parameters of different arity → no pair.

## Agent execution notes

- If any test would require similarity scoring to pass, the test is wrong — stop and ask.
- Determinism: never iterate a set to build the pair map; sort before pairing.
