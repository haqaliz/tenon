# Plan: diff-core — 2026-10-25

Sources: `docs/planning/openapi-differ/prd.md`, `docs/planning/openapi-differ/diff-core/spec.md`.

## Prerequisites

`change-record` (types) and `spec-ingest` (resolved dicts) merged.

## Phases

### Phase 1: Paths and operations (TDD)

- **Files:** `src/tenon/detect/diff.py`, `tests/detect/test_diff_paths.py`,
  `tests/fixtures/specs/paths-old.yaml`, `paths-new.yaml`
- **Steps:**
  1. Tests: removed path → one `endpoint_removed` per method with `path` set and pointer `#/paths`;
     removed method on surviving path → pointer `#/paths/~1<escaped-path>`; added method →
     `endpoint_added`, `breaking=False`.
  2. Implement `diff(old, new)` returning `DiffResult`, starting with the paths walk.
  3. Implement RFC 6901 escaping for path segments.
- **Validation:** `uv run pytest tests/detect/test_diff_paths.py`
- **Commit:** `feat(detect): diff paths and operations`

### Phase 2: Parameters, including path-level inheritance (TDD)

- **Files:** `src/tenon/detect/diff.py`, `tests/detect/test_diff_params.py`, fixtures.
- **Steps:**
  1. Tests: removed parameter (`breaking=True`); optional → required (`parameter_required_added`);
     new required parameter; `type` change; a parameter declared only at path level and removed
     there is reported once per operation that inherited it.
  2. Implement merge of path-level and operation-level params keyed by `(name, in)`, operation wins.
  3. Pointer is `…/parameters` of the operation (or of the path item when path-level).
- **Validation:** `uv run pytest tests/detect/test_diff_params.py`
- **Commit:** `feat(detect): diff parameters with path-level inheritance`

### Phase 3: Schemas (TDD)

- **Files:** `src/tenon/detect/diff.py`, `tests/detect/test_diff_schemas.py`, fixtures.
- **Steps:**
  1. Tests: property removed (breaking), required added (breaking), optional added (not breaking),
     type changed, enum narrowed vs widened, array items recursed, nested object recursed.
  2. Tests: a schema changed once in `components` produces one change, not one per `$ref` user.
  3. Implement `_diff_schema(old, new, pointer)` recursion with cycle guard on `(old_id, new_id)`.
  4. Implement components-level `schema_added`/`schema_removed`.
- **Validation:** `uv run pytest tests/detect/test_diff_schemas.py`
- **Commit:** `feat(detect): diff request, response and component schemas`

### Phase 4: Composition policy + 3.0/3.1 normalisation (TDD)

- **Files:** `src/tenon/detect/diff.py`, `tests/detect/test_diff_composition.py`, fixtures.
- **Steps:**
  1. Tests: `oneOf` in a parameter schema → `UNSUPPORTED_COMPOSITION` at the exact pointer; plain
     `allOf` merge is traversed; `allOf` with `discriminator` refuses; nullability-only change
     produces zero changes (3.0 `nullable` vs 3.1 type array).
  2. Implement `normalise_type(schema) -> (types: frozenset, format, nullable)`; use it for every
     type comparison.
  3. Implement the `allOf` plain-merge check; refuse otherwise.
- **Validation:** `uv run pytest tests/detect`
- **Commit:** `feat(detect): composition policy and 3.0/3.1 type normalisation`

## File-by-file build order

1. `src/tenon/detect/diff.py` — `diff`, `_diff_paths`, `_diff_operation`, `_diff_parameters`,
   `_diff_schema`, `_normalise_type`. Depends on `record.py` only (input already resolved).
2. `src/tenon/detect/__init__.py` — export `diff`.
3. `tests/detect/test_diff_*.py` + `tests/fixtures/specs/*`.

## Testing strategy

- One fixture pair per change kind, plus the negative pair from the spec's acceptance criteria.
- A property test over key order: shuffle dict keys deterministically, assert identical `to_json()`.

## Edge cases

- `paths` absent or `{}` in one document → zero changes, not a crash.
- `$ref` already resolved by ingest, so no `$ref` handling here; a lingering `$ref` is a bug and
  should raise `UNRESOLVED_REF`, not be ignored.
- Response schemas: removal/type-change `breaking=True`, addition `breaking=False` (assumption
  recorded in the spec's open question).
- `required` lists are order-insensitive; compare as sets.

## Agent execution notes

- Do not add a `parameter_added` kind — the PRD's list is closed; it is a known gap.
- Stop and ask if a fixture cannot express a kind without inventing spec features.
