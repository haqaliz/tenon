## Phase 1: Refactor the fix flow and add the command

- **Goal:** `provider migrate` runs the same pipeline.
- **Prerequisites:** `provider-bundle`.
- **Files:** `cli/main.py`, `cli/report.py`, tests.
- **Steps:**
  1. Extract `_fix_results(repo, old, new, config, remote, *, open_pr, allow_below) ->
     (changes, results)`; `_fix` calls it and renders the fix report; behavior unchanged.
  2. Write failing tests: a valid bundle on the `proof-basic` repo exits 0 with a `TESTS_PASSED`
     proof; a red check exits 1; the checkout is unchanged; `--check`/`--require` override.
  3. Run — red; add the `provider migrate` parser/dispatch and the config mapping; green.
- **Validation:** `uv run pytest tests/cli/test_main.py -k provider`.
- **Commit:** `feat(cli): run a provider migration bundle`

## Phase 2: The provider report

- **Goal:** text and the provider JSON envelope.
- **Prerequisites:** Phase 1.
- **Files:** `cli/report.py`, `cli/main.py`, tests.
- **Steps:**

- **Validation:** `uv run pytest tests/cli/test_main.py -k "provider and (json or text)"`.

## Phase 3: PR, overrides and errors

- **Goal:** the shipped PR path and named failures.
- **Prerequisites:** Phase 2.

## Edge cases & error handling

- The bundle's old/new paths are used directly; a missing file is a bundle error.
- `--check`/`--require` override the bundle.
- The provider envelope is additive; the fix envelope is unchanged.
- No PR branding.
