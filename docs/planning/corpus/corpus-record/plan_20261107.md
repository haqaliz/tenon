## Phase 1: Outcome, record and id

- **Goal:** one validated record with a deterministic id.
- **Prerequisites:** none.
- **Files:** `record.py`, `test_record.py`.
- **Steps:**
  1. Write failing tests: the six outcomes; a valid record round-trips; empty repo/commit, non-dict
     change/proposal/proof, a bad date, a non-Outcome and an id mismatch raise `ValueError`; the id
     is stable/changes with the diff/commit/change and ignores the outcome.
  2. Run — red; implement; green.
- **Validation:** `uv run pytest tests/corpus/test_record.py -k "record or id or outcome"`.
- **Commit:** `feat(corpus): add the corpus record and id`

## Phase 2: Load and append

- **Goal:** a JSONL history that keeps order.
- **Prerequisites:** Phase 1.
- **Files:** `store.py`, `test_store.py`.
- **Steps:**
  1. Write failing tests: two lines load in order; blank lines ignored; a missing file and a
     malformed line are `CorpusError`; append to a new/existing file creates canonical lines and
     keeps previous records; a missing parent dir is created.
  2. Run — red; implement; green.
- **Validation:** `uv run pytest tests/corpus/test_store.py -k "load or append"`.
- **Commit:** `feat(corpus): append and load the corpus`

## Phase 3: Outcome update and errors

- **Goal:** update a human outcome without losing history.
- **Prerequisites:** Phase 2.
- **Files:** `store.py`, `test_store.py`.
- **Steps:**
  1. Write failing tests: update changes only the outcome/url/notes and keeps the id/order; a
     missing id is a `CorpusError`; the file is written atomically (no partial line); an invalid
     record on load names the line.
  2. Run — red; implement the temp+replace rewrite; green.
- **Validation:** `uv run pytest tests/corpus/test_store.py`.
- **Commit:** `feat(corpus): update corpus outcomes`

## Phase 4: Exports and determinism

- **Goal:** the public surface and byte-stable JSON.
- **Prerequisites:** Phase 3.
- **Files:** `__init__.py`, tests.
- **Steps:** add the exports, a package import test and a hash-seed/double-run stability test; run

## Testing strategy

- `tmp_path` JSONL files; no network; fixed dates.
- One test per acceptance criterion, cited as `# Spec AC<n>`.

## Environment & secrets

## Edge cases & error handling

- A missing file is an error on load; append creates.
- A malformed line names the line; a blank line is ignored.
- The id is a run identity; the outcome is not part of it.
- The update rewrites atomically with the same order.
