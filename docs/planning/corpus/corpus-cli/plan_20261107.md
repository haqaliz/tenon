## Phase 1: `corpus record`

- **Goal:** a `tenon fix --json` file becomes records.
- **Prerequisites:** `corpus-record`.
- **Files:** `cli/main.py`, tests.
- **Steps:**
  1. Write failing tests: a valid fix JSON with two results appends two records; ids are
     deterministic; repo/commit/outcome/date/notes/evidence carried; `--json` lists the ids; a
     non-fix JSON/missing results/missing result key/bad date/unknown outcome exits 2 with no
     partial append.
  2. Run — red; implement the nested parser and the record path; green.
- **Validation:** `uv run pytest tests/cli/test_main.py -k "corpus and record"`.
- **Commit:** `feat(cli): record a fix run in the corpus`

## Phase 2: `corpus outcome` and `corpus report`

## Testing strategy

- A fix JSON fixture built from a real `render_fix_json` shape; fixed dates; `tmp_path` corpora.
- One test per acceptance criterion, cited as `# Spec AC<n>`.

## Environment & secrets

- None.

## Edge cases & error handling

- A bad fix JSON appends nothing.
- An unknown id/outcome/date exits 2 with a named error.
- The seed ids are computed, not hand-written.
- The report is descriptive; the README says no merge outcome exists yet.
