## Phase 1: Grouping and counts

- **Goal:** per-level/per-outcome counts over the records.
- **Prerequisites:** `corpus-record`.
- **Files:** `report.py`, `test_report.py`.
- **Steps:**
  1. Write failing tests: two levels with mixed outcomes produce the right `count`/per-outcome
     counts; all five levels and six outcomes are present (zero-filled); total.
  2. Run — red; implement; green.
- **Validation:** `uv run pytest tests/corpus/test_report.py -k "group or count"`.
- **Commit:** `feat(corpus): group corpus records by level and outcome`

## Phase 2: Known outcomes and the merge rate

- **Goal:** never call a local/pending record a success.
- **Prerequisites:** Phase 1.
- **Files:** `report.py`, `test_report.py`.
- **Steps:**
  1. Write failing tests: `merged=1, rejected=1` -> 0.5; `known=0` -> None; `local_only`/`pending`
     do not change `known`; `closed` is known but not merged; an unknown proof level raises
     `CorpusError` with the id.
  2. Run — red; implement; green.
- **Validation:** `uv run pytest tests/corpus/test_report.py -k "rate or known"`.
- **Commit:** `feat(corpus): compute the honest merge rate`

## Phase 3: Text, JSON and the empty report

- **Goal:** one stable report for machines and humans.
- **Prerequisites:** Phase 2.
- **Files:** `report.py`, `test_report.py`.
- **Steps:**
  1. Write failing tests: the exact JSON keys/order; the text table with `n/a`; an empty corpus is
     valid (zeros, null rates); byte stability across runs.
  2. Run — red; implement; green.
- **Validation:** `uv run pytest tests/corpus/test_report.py`.
- **Commit:** `feat(corpus): render the corpus report`

## Edge cases & error handling

- The report includes zero rows for absent levels/outcomes.
- A null rate is `None` in JSON and `n/a` in text.
- An unknown proof level is a named error, not a silent skip.
