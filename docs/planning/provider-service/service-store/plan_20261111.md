## Phase 1: Schema, create and get

- **Goal:** a durable queued run.
- **Prerequisites:** none.
- **Files:** `store.py`, `__init__.py`, tests.
- **Steps:**
  1. Write failing tests: create -> queued with a uuid4 hex id and a UTC timestamp; get; unknown ->
     None; two creates; idempotency returns the existing run; reopening preserves the row.
  2. Run — red; implement the schema and create/get/open; green.
- **Validation:** `uv run pytest tests/service/test_store.py -k "create or get or reopen"`.
- **Commit:** `feat(service): add the SQLite run store`

## Phase 2: Claim, finish and list

- **Goal:** the queue and the status transitions.
- **Prerequisites:** Phase 1.

## Phase 3: Events and the full suite

- **Goal:** the deduplicated webhook log.
- **Prerequisites:** Phase 2.
- **Files:** `store.py`, tests.
- **Steps:**

## Testing strategy

- `tmp_path` SQLite files; injected `now`/`new_id` for determinism; no network.
- One test per acceptance criterion, cited as `# Spec AC<n>`.

## Environment & secrets

- None.

## Edge cases & error handling

- `:memory:` works through the single connection.
- A duplicate idempotency key is not an error.
- A finish on an unknown/queued->succeeded transition is a `ValueError`.
- The store is serialized by a lock; the worker and request threads share one object.
