## Phase 1: Runner and worker

- **Goal:** a run executes the shipped CLI and lands in the store.
- **Prerequisites:** `service-store`.
- **Files:** `runner.py`, `worker.py`, tests.
- **Steps:**
  1. Write failing tests: a fake `runner` returns a JSON envelope (exit 0/1); exit 2 with stderr;
     non-JSON; timeout; OSError; the argv is built from the bundle. Worker: `run_once` success/exit
     1/exception/FIFO/empty; `start/stop` with a stop event.
  2. Run — red; implement; green.
- **Validation:** `uv run pytest tests/service/test_runner.py tests/service/test_worker.py`.
- **Commit:** `feat(service): run a bundle in the worker`

## Phase 2: The API handler

- **Goal:** a pure, guarded JSON API.
- **Prerequisites:** Phase 1.
- **Files:** `api.py`, tests.
- **Steps:**
  1. Write failing tests: auth; `POST /runs` valid/idempotency/traversal/absolute/missing/non-json/
     big body; `GET /runs/{id}`/list/limit; health; unknown 404; wrong method 405; webhook no
     secret/bad signature/valid/duplicate/malformed.
  2. Run — red; implement `Api.handle` and the canonical JSON; green.
- **Validation:** `uv run pytest tests/service/test_api.py`.
- **Commit:** `feat(service): expose the run API`

## Phase 3: The server and `provider serve`

- **Goal:** the CLI command starts the worker + server.
- **Prerequisites:** Phase 2.
- **Files:** `http.py`, `cli/main.py`, tests.
- **Steps:**
  1. Write failing tests: the parser flags; missing token/bundles/db parents exit 2; the
     `--remote` guard does not crash `serve`; the command builder includes `--installed`, `--json`,
     the app flags and `--open-pr` only when not `--dry-run`; the server wrapper calls the API (a
     localhost smoke test or a handler unit test).
  2. Run — red; implement `serve` and `_serve`; green.
- **Validation:** `uv run pytest tests/cli/test_main.py -k serve`.
- **Commit:** `feat(cli): serve the provider API`

## Phase 4: End-to-end and docs

- **Goal:** POST -> worker -> GET with the same report; documented.
- **Prerequisites:** Phase 3.
- **Files:** tests, README, ARCHITECTURE.
- **Steps:**
  1. Write an end-to-end test: an `Api` with a real `RunStore`, a `Worker` with a fake runner; POST a
     run, `run_once`, GET the run, assert the report/summary/exit.
  2. Document the command, endpoints, security model and limits.
- **Validation:** `uv run pytest` (2,099 + new tests); `uv run tenon provider serve --help`.
- **Commit:** `docs: document the provider service`

## Testing strategy

- Pure `Api.handle` with a temp SQLite; fake `subprocess.run`/runner; no sockets except one localhost
  smoke test if stable; no GitHub/network.
- One test per acceptance criterion, cited as `# Spec AC<n>`.

## Environment & secrets

- Test tokens/secrets are literals; the app key path is a temp file.

## Edge cases & error handling

- The token/secret never appear in a response or the DB.
- Bundle names are confined; a symlink escape is rejected.
- A run error is capped; a timeout kills the child.
- The `serve` parser must not hit the `--remote` guard.
