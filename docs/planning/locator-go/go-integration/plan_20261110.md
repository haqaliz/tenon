## Phase 1: Config and language plumbing

- **Goal:** `go` is a valid language and `package_name` reaches the config.
- **Prerequisites:** `go-locate`.
- **Files:** `cli/config.py`, `cli/main.py`, tests.
- **Steps:**
  1. Write failing tests: `CliConfig(language="go")`; a temp `tenon.toml` with `language = "go"` and
     `package_name`; `--language go --sdk-package <root> --package-name <name>` with no config;
     `mcp` + `go` rejected; the error names python/ts/rust/go.
  2. Run — red; extend `LANGUAGES`, the literal, the messages, the `LOCATE_TYPES` build (including
     `package_name` for Go) and `overrides`; green.
- **Validation:** `uv run pytest tests/cli/test_main.py -k "language or go"`.
- **Commit:** `feat(cli): accept the Go language`

## Phase 2: Locator and bundle dispatch

- **Goal:** `check`/`fix`/`provider migrate` use the Go locator.
- **Prerequisites:** Phase 1.
- **Files:** `cli/main.py`, `provider/bundle.py`, tests.
- **Steps:**
  1. Write failing tests: `_locate` dispatches go; a Go bundle loads with `GoLocateConfig` including
     `package_name`; `mcp`+go, a bad root and a bad package are named bundle errors; the parser lists
     go and accepts `--package-name`.
  2. Run — red; add the locator table and bundle dispatch; green.
- **Validation:** `uv run pytest tests/provider/test_bundle.py tests/cli/test_main.py -k "go"`.
- **Commit:** `feat(cli): dispatch the Go locator`

## Phase 3: Fixture, end-to-end and docs

- **Goal:** a real Go checkout through check/fix and a bundle.
- **Prerequisites:** Phase 2.
- **Files:** fixture, tests, README, ARCHITECTURE.
- **Steps:**
  1. Add `tests/fixtures/repos/go-basic/` with `go.mod` and a `main.go` (root + `charge` subpackage
