## Testing strategy

- Copy fixture repos into `tmp_path` before any test that could conceivably write; the read-only
  test hashes the committed tree.
- Exactly one subprocess test (`git apply`); everything else in-process.
- Full suite before each commit.

## Edge cases

- Two edits in different files: independent application and hunks.
- A file with no trailing newline: `difflib` output must not invent one; normalise once at the end.
- An edit on line 1 with three lines of context: header hunk starts at `@@ -1,4 +1,4 @@`.
- `dict_key` with mixed quotes on the same line: use the quote at the edit column, not a fixed one.
- A stale file missing entirely between locate and propose: `STALE_SITE`, no exception.
- Windows separators: paths from `Site` are already `/`; reject anything else with a backslash at
  the safety check.

## Agent execution notes

- The assembly is the trust boundary: a `Proposer` may propose anything, but nothing is edited
  without `verify`, and no ambiguous site is ever edited. Do not let the fake proposer bypass it.
- Do not run `git apply` against the real repository. Copy under `tmp_path`.
- Do not add a CLI, logging, or "dry run" flags.
