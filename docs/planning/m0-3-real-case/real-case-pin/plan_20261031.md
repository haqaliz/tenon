## Testing strategy

- Unit: the change record shape (T1) from the minimal pair.
- Integration: `locate` + `propose` over the pinned snapshot.
- Determinism: two proposals byte-identical.
- Full suite offline; the fixture test makes no network call.

## Edge cases

- If T1 infers a different kind (property add/remove instead of rename), the minimal pair is wrong:
  keep exactly one removed property and one added property under the same pointer, as in the plan.
- If the upstream line numbers drift, the snapshot is wrong — the fixture is pinned, so line 41 and
  line 49 are contract, not coincidence.
- A `git apply --check` is not part of this aspect; the diff's applicability is proven by T4 in the
  evidence run. If desired, add it later in `tests/propose/`, not here.
