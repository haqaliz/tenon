## Phase 1: Config and the dependency

- **Goal:** a validated Rust config.
- **Prerequisites:** none.
- **Files:** `pyproject.toml`, `rust_config.py`, tests.
- **Steps:**
  1. `uv add tree-sitter-rust`; confirm the import works.
  2. Write failing tests: a valid crate; blank/`::`/path/slash are named `ValueError`s; mappings are
     read-only copies.
  3. Run — red; implement; green.
- **Validation:** `uv run pytest tests/locate/test_rust_config.py`.
- **Commit:** `feat(locate): add the Rust locate config`

## Phase 2: Rooting and calls

- **Goal:** `use`/alias roots and associated calls as `Hit`s.
- **Prerequisites:** Phase 1.
- **Files:** `rust_scan.py`, tests.
- **Steps:**
  1. Write failing tests on temp `.rs` files: simple/grouped/nested/`as`/crate-alias/`self` imports;
     glob; bare crate path; associated calls and aliases with canonical chains; an unrooted method
     call is not a hit; no crate import -> empty `modules`; skip `target`/`vendor`/hidden.
  2. Run — red; implement the parser cache, file walk, `use` extraction and call hits; green.
- **Validation:** `uv run pytest tests/locate/test_rust_scan.py -k "root or call or files"`.
- **Commit:** `feat(locate): scan Rust imports and calls`

## Phase 3: Struct literals and field access

- **Goal:** field evidence on the right chain.
- **Prerequisites:** Phase 2.
- **Files:** `rust_scan.py`, tests.
- **Steps:**
  1. Write failing tests: a standalone rooted struct literal's `KEYWORD` fields; an inline literal
     in a rooted call; a `let` binding passed to a rooted call; a rebinding replaces the name; a
     field access through a binding is an `ATTRIBUTE` hit with the type and call chains.
  2. Run — red; implement per-function binding tracking and call-argument attribution; green.
- **Validation:** `uv run pytest tests/locate/test_rust_scan.py -k "struct or field or binding"`.
- **Commit:** `feat(locate): locate Rust struct fields`

## Phase 4: The wrapper and policy integration

- **Goal:** the shared `LocateResult` for Rust changes.
- **Prerequisites:** Phase 3.
- **Files:** `rust_locate.py`, `__init__.py`, `test_rust_locate.py`.
- **Steps:**
  1. Write failing tests: an operation change with a mapped `Charge.create` and a field on the call
     chain; a component-scope field rename; `UNROOTED_RECEIVER`, `UNMAPPED_SYMBOL`,
     `MULTIPLE_CANDIDATES`, `NO_SITES`/`NO_SDK_IMPORT` as the shared rules decide; export tests.
  2. Run — red; implement the wrapper and exports; green.
- **Validation:** `uv run pytest tests/locate/test_rust_*.py`; full suite.
- **Commit:** `feat(locate): apply the certainty policy to Rust`

## Testing strategy

- Temp `.rs` files for scanner tests; `Change` fixtures copied from `tests/locate/test_stripe_shape.py`
  for policy tests; deterministic file order; no network/toolchain.
- One test per acceptance criterion, cited as `# Spec AC<n>`.

## Environment & secrets

- None; the grammar is a core dependency.

## Edge cases & error handling

- A glob roots only paths through the crate.
- A method call/macro is unseen, never a guess.
- A local module named like the crate is a documented false positive.
- Rebinding a name clears the previous struct.
