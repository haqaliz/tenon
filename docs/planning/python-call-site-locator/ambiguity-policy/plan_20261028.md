## Rule table (implement exactly this order)

| # | Condition | Outcome |
|---|---|---|
| 1 | `query.reason is not None` | `LocateResult.reason = query.reason`, empty lists |
| 2 | `scan.modules == ()` | `NO_SDK_IMPORT` |
| 3 | scope `operation`, `query.origin == "none"` | `OPERATION_NOT_MAPPED` |
| 4 | scope `operation`, ≥2 operation candidates have rooted `call` hits | one `MULTIPLE_CANDIDATES` group |
| 5 | scope `operation`, no candidate has a rooted `call` hit | `NO_SITES` |
| 6 | scope `operation`, field `must_exist` | rooted `keyword`/`dict_key` hits with matching symbol **and** `chain` equal to the resolved call chain → certain |
| 7 | scope `operation`, field `must_exist`, resolved call has `star_kwargs` | `DYNAMIC_KWARGS` group with the call site |
| 8 | scope `operation`, field `must_be_added` | the resolved call sites are certain; matching rooted keyword hits also certain |
| 9 | scope `component`, rooted hits matching `field_name` | certain |
| 10 | scope `component`, non-rooted matching hits | one `UNROOTED_RECEIVER` group, all candidates |
| 11 | `alias_chain` dynamic whose symbol matches, or whose enclosing call chain matches | `ALIAS_CHAIN` group |
| 12 | `getattr` dynamic naming `field_name` or the resolved operation leaf | `DYNAMIC_GETATTR` group |
| 13 | nothing matched | `NO_SITES` |

`UNMAPPED_SYMBOL` is emitted when a mapped `field_name` has no rooted hits but a *different*
spelling of the same spec field does (only detectable when the mapping key matched and the mapped
target differs from `change_field`): the differing hits become an `UNMAPPED_SYMBOL` group. If the
mapping did not match, this case cannot arise and rule 13 applies.

## Testing strategy

- Two layers: `resolve` with literal inputs (fast, exhaustive rules) and `locate` over committed
  repos (proves the wiring). Do not duplicate the rule matrix in the integration file.
- The decoy test is a release gate: if it ever fails, T2 is unsafe regardless of other green tests.
- Full suite before each commit: `.venv/bin/python -m pytest -q`.

## Edge cases

- A change whose field appears both rooted and unrooted: rooted sites certain, unrooted in a group;
  never drop either.
- An operation query with a field but **zero** resolved calls: rule 5 (`NO_SITES`) fires before
  field rules — do not report field hits from unrelated operations as certain.
- A `getattr` dynamic with `symbol=None` is not attributable to a specific field; ignore it unless
  its enclosing chain matches the operation (then `DYNAMIC_GETATTR`).
- Deterministic grouping: a single group per reason, candidates merged and deduplicated, sorted by
  aspect 1. Never emit two groups with the same reason and symbol.
- `alias_chain` containing the field name is not proof of a site; it stays a group with the alias
  assignment line as the candidate.

## Agent execution notes

- All certainty logic lives here. If a rule needs information the scan does not carry, stop and
  raise it rather than adding a second scan.
- Do not promote `UNROOTED_RECEIVER` for "obvious" wrappers; the spec's open question answers no.
- Do not add ranking, scoring, or "best candidate" selection. T3 chooses, T2 only reports.
- If a fixture test and the spec disagree, the spec wins; update the fixture, not the rule —
  unless the rule is unrepresentable, in which case stop and ask.
