## Phase 1: Config and the tool gate

- **Goal:** a valid `McpLocateConfig` and one tool-scoped `Change` accepted.
- **Prerequisites:** `mcp-scan`.
- **Files:** `src/tenon/locate/mcp_config.py`, `tests/locate/test_mcp_locate.py`.
- **Steps:**
  1. Write failing tests: default `"mcp"` and a submodule package construct; empty/whitespace/path-like
     names raise; a non-tool `Change` -> `UNSUPPORTED_CHANGE_KIND`; a tool `Change` runs the scan.
  2. Run — red; implement the config and the gate; green.
- **Validation:** `uv run pytest tests/locate/test_mcp_locate.py -k "config or tool"`.
- **Commit:** `feat(locate): add the MCP locate config`

## Phase 2: Certain calls and field keys

- **Goal:** the rooted+literal certainty.
- **Prerequisites:** Phase 1.
- **Files:** `src/tenon/locate/mcp_locate.py`, fixtures, tests.
- **Steps:**
  1. Write failing tests: a rooted `async with` call -> a certain `call` site with the exact
     line/column; a renamed/removed/type/enum field -> a certain `dict_key`/`keyword` site; a
     required-added with no key -> the call site; the `change` passes through.
  2. Run — red; implement the call/field filters; green.
- **Validation:** `uv run pytest tests/locate/test_mcp_locate.py -k "call or field"`.
- **Commit:** `feat(locate): locate MCP tool calls and argument keys`

## Phase 3: Ambiguity, reasons and output

- **Goal:** every unprovable case is a named group/reason.
- **Prerequisites:** Phase 2.
- **Files:** `src/tenon/locate/mcp_locate.py`, tests.
- **Steps:**
  1. Write failing tests: dynamic tool -> `DYNAMIC_GETATTR`; variable/`**` payload ->
     `DYNAMIC_KWARGS`; unrooted matching call -> `UNROOTED_RECEIVER` with the call and candidate
     key; second-hop alias -> `ALIAS_CHAIN`; no MCP import -> `NO_SDK_IMPORT`; no matching tool ->
     `NO_SITES`; a schema kind -> `UNSUPPORTED_CHANGE_KIND`; an `/outputSchema` property -> the call
     site only.
  2. Run — red; implement the groups/reasons; green.
- **Validation:** `uv run pytest tests/locate/test_mcp_locate.py`.
- **Commit:** `feat(locate): pin MCP ambiguity and reasons`

## Testing strategy

- Fixture repos; `Change` records built through `diff_mcp` or directly.
- One test per acceptance criterion, cited as `# Spec AC<n>`.
- Assert exact sites, group reasons/candidates and byte-stable JSON.

## Environment & secrets

- None.

## Edge cases & error handling

- A field kind with no payload name is treated as a tool-level call-site change.
- A `RENAMED` field uses `before`; a `RENAMED` tool (two endpoint records) locates each call.
- An output-schema change stops at the call site.
- A dynamic tool name cannot be attributed; the group holds the call.
