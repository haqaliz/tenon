## Phase 1: Summary, title and commit

- **Goal:** one deterministic human summary reused by the title and commit.
- **Prerequisites:** `pr-result`.
- **Files:** `tests/pr/test_render.py` (new), `src/tenon/pr/render.py` (new).
- **Steps:**
  1. Write failing tests with a `Change(kind=RENAMED, location=Location(method="post",
     path="/v1/checkout/sessions", pointer=...), before="payment_method_types",
     after="allowed_payment_method_types")` and a hand-built `ProofResult`:
     - title is `[TESTS_PASSED] tenon: renamed POST /v1/checkout/sessions: payment_method_types ->
       allowed_payment_method_types`;
     - commit message is the same summary with the `tenon: ` prefix and no level;
     - a change with no method/path uses the pointer;
     - int, bool, `None`, dict and list before/after values render deterministically (dict/list as
       compact canonical JSON).
  2. Run — red.
  3. Implement `_summary(change)`, `_scalar(value)` and `_title(proof, summary)`.
  4. Run — green.
- **Validation:** `uv run pytest tests/pr/test_render.py -k "summary or title or commit"`.
- **Commit:** `feat(pr): render the PR summary, title and commit subject`

## Phase 2: Branch name

- **Goal:** a readable, collision-resistant, deterministic branch.
- **Prerequisites:** Phase 1.
- **Files:** `src/tenon/pr/render.py`, `tests/pr/test_render.py`.
- **Steps:**
  1. Write failing tests:
     - regex `^tenon/[a-z0-9-]+-[0-9a-f]{8}$`;
     - same change + same diff → identical branch;
     - a one-byte diff change → a different suffix;
     - a unicode/punctuation symbol → a valid slug (no empty slug, no doubled dashes);
     - a 200-character summary → slug truncated to 48 characters before the hash.
  2. Run — red.
  3. Implement `_slug(summary)` and `_branch(change, diff)` using
     `sha256(change.to_json().encode() + b"\0" + diff.encode())`.
  4. Run — green.
- **Validation:** `uv run pytest tests/pr/test_render.py -k branch`.
- **Commit:** `feat(pr): render a deterministic PR branch name`

## Phase 3: Body for `TESTS_PASSED`

- **Goal:** the exact body a reviewer reads when a check passed.
- **Prerequisites:** Phase 2.
- **Files:** `src/tenon/pr/render.py`, `tests/pr/test_render.py`, `tests/pr/conftest.py`.
- **Steps:**
  1. Add shared builders to `conftest.py`: `a_rename_proposal()` (use the `proof-basic` fixture and
     the real T1→T2→T3 path, mirroring `tests/prove/test_prove.py`), `a_passed_proof()`,

  2. Write failing tests for the ordered sections: heading, fixed level sentence, `### Change`,

     command and both exit codes; assert every `proposal.files` path and every skipped reason; assert
     `--- a/` is absent; assert the body ends with exactly one newline.
  3. Run — red.
  4. Implement `_body(proposal, proof, unanalyzed)` with fixed strings and `_code(text)`.
  5. Run — green.
- **Validation:** `uv run pytest tests/pr/test_render.py -k passed`.
- **Commit:** `feat(pr): render the PR body for a passed proof`

## Phase 4: Body for `UNVERIFIED`

- **Goal:** a flagged suggestion that never reads as a pass.
- **Prerequisites:** Phase 3.
- **Files:** `src/tenon/pr/render.py`, `tests/pr/test_render.py`.
- **Steps:**
  1. Write failing tests: heading `UNVERIFIED`; `Cause: <exact value>`; the fixed
     "Nothing was proven" sentence; the flagged-suggestion sentence; missing baseline/after render
     `not run`; a timeout renders `timed out`; a non-empty `after.stdout_tail` appears in a fenced
     block. Assert the fixed strings, not a naive substring check on `PASSED`.
  2. Run — red.
  3. Implement the UNVERIFIED branch of `_level_sentence`, `_check_section` and `_what_this_proves`.
  4. Run — green.
- **Validation:** `uv run pytest tests/pr/test_render.py -k unverified`.
- **Commit:** `feat(pr): render a flagged PR body for an unverified proof`

## Phase 5: Skipped sites, unanalyzed subtrees, escaping and stability

- **Goal:** nothing Tenon refused or could not analyze disappears; the output is byte-stable.
- **Prerequisites:** Phase 4.
- **Files:** `src/tenon/pr/render.py`, `tests/pr/test_render.py`.
- **Steps:**
  1. Write failing tests:
     - every `proposal.skipped` entry appears as `path:line`, symbol, reason; `None.` when empty;
     - a supplied `Unanalyzed(pointer, reason)` list appears; an empty list omits the section;
     - a symbol/path containing a backtick or newline is sanitised and cannot break the inline span;
     - `to_json()` of the draft is byte-identical across `PYTHONHASHSEED` values;
     - the body contains no absolute fixture path, no `2026-` timestamp, no `ProofResult(`/enum repr.
  2. Run — red.
  3. Implement the remaining sections and the escape helper; run the whole file.
  4. Run — green.
- **Validation:** `uv run pytest tests/pr/test_render.py` and then `uv run pytest`.
- **Commit:** `feat(pr): complete the PR body and pin determinism`

## Testing strategy

- Golden strings for the happy path; targeted assertions for every section and refusal.
- Property-style checks for determinism (same inputs twice, hash seeds).
- No filesystem writes from the renderer; the fixture repo is read-only.
- Tests cite `# Spec AC<n>`.

## Environment & secrets

- None. No network, no `gh`, no git required.

## Edge cases & error handling

- Non-string before/after values use canonical JSON; sets are not expected but would need a stable
  sort if they appear (T1 emits JSON types only).
- A summary longer than the slug budget is truncated before hashing; the hash still covers the full
  change and diff.
- A symbol containing a markdown fence is treated as text; only inline spans are sanitised.
- An `UNVERIFIED` body with a huge tail is capped by `tenon.prove.tail` before rendering.
