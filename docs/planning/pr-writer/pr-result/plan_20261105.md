## Phase 1: Closed refusal and status vocabularies

- **Goal:** pin the two enums before any other type exists.
- **Prerequisites:** none.
- **Files:** `tests/pr/test_result.py` (new), `src/tenon/pr/result.py` (new).
- **Steps:**
  1. Write failing tests that assert `[value.value for value in PrStatus] == ["OPENED", "REFUSED"]`
     and the exact thirteen `PrRefusal` values from the spec, in order.
  2. Add round-trip tests: every value constructs from its string; every value appears as a plain
     string in a future `to_dict()`.
  3. Run `uv run pytest tests/pr/test_result.py` — red because `tenon.pr.result` does not exist.
  4. Implement the two `StrEnum`s in `src/tenon/pr/result.py`. Add `src/tenon/pr/__init__.py` with
     only the enum exports for now.
  5. Run the tests — green.
- **Validation:** `uv run pytest tests/pr/test_result.py`.
- **Commit:** `feat(pr): pin the PR status and refusal vocabularies`

## Phase 2: `PrDraft`

- **Goal:** one frozen, non-empty draft type with byte-stable JSON.
- **Prerequisites:** Phase 1.
- **Files:** `src/tenon/pr/result.py`, `tests/pr/test_result.py`.
- **Steps:**
  1. Write failing tests: a valid draft round-trips through `to_dict()` with exactly the keys
     `title`, `body`, `branch`, `commit_message`; each empty field raises `ValueError`; assignment
     after construction raises `FrozenInstanceError` (or `AttributeError`); `to_json()` is
     byte-identical across `PYTHONHASHSEED` values via a subprocess helper, as in
     `tests/prove/test_result.py`.
  2. Run — red.
  3. Implement `@dataclass(frozen=True, slots=True) class PrDraft` with a `__post_init__` that
     rejects empty/non-string fields, plus `to_dict()` / `to_json()`.
  4. Run — green.
- **Validation:** `uv run pytest tests/pr/test_result.py -k draft`.
- **Commit:** `feat(pr): add the PrDraft contract`

## Phase 3: `PrResult`

- **Goal:** the opened-or-refused answer with invariants and JSON.
- **Prerequisites:** Phase 2; `ProofLevel` from `tenon.prove`.
- **Files:** `src/tenon/pr/result.py`, `tests/pr/test_result.py`.
- **Steps:**
  1. Write failing tests:
     - `OPENED` with a URL and no refusal is valid; `OPENED` without a URL raises; `OPENED` with a
       refusal raises.
     - `REFUSED` with a refusal and no URL is valid; `REFUSED` without a refusal raises; `REFUSED`
       with a URL raises.
     - String `status`, `level` and `refusal` coerce to enums.
     - `detail` defaults to `""`; a refusal can carry a tail.
     - `to_dict()` keys are exactly `status`, `level`, `draft`, `url`, `refusal`, `detail`;
       `to_json()` holds only JSON primitives and is hash-seed stable.
  2. Run — red.
  3. Implement `PrResult` with `__post_init__` invariants, enum coercion and serialisation.
  4. Run — green.
- **Validation:** `uv run pytest tests/pr/test_result.py` (all green).
- **Commit:** `feat(pr): add the PrResult contract`

## Testing strategy

- Unit tests only; no subprocess except the hash-seed stability helper.
- One test per acceptance criterion, cited in a comment as `# Spec AC<n>`.
- No filesystem fixture needed in this aspect.

## Environment & secrets

- None. No network, no `gh`, no git required for this aspect.

## Edge cases & error handling

- Empty fields are rejected at construction, not at render time.
- A refusal with an empty `detail` is valid; the detail is never parsed.
- Enum coercion accepts strings so JSON round-trips are easy; invalid strings raise `ValueError`
  from the enum constructor.

## Agent execution notes

- Implement strictly test-first; each phase ends with a green targeted run and a commit.
- Do not add a `merge` status or a `CLOSED` status.
- Do not import `subprocess` or `pathlib` in `result.py`.
- If a test needs a valid `ProofLevel`, import it from `tenon.prove`.
