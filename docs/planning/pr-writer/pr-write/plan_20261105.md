## Phase 1: Preconditions and the level gate

- **Goal:** every refusal that does not need a clone is named and side-effect free.
- **Prerequisites:** `pr-result`, `pr-render`.
- **Files:** `tests/pr/test_write.py` (new), `tests/pr/conftest.py` (new),
  `src/tenon/pr/write.py` (new), `src/tenon/pr/remote.py` (protocol only).
- **Steps:**
  1. In `conftest.py`, add `FakeRemote` recording `default_branch`, `branch_exists`, `push` and
     `create_pr` calls, with configurable `default` and `existing` values, and a
     `repo_with_remote(tmp_path)` fixture that creates a bare repo (`git init --bare
     --initial-branch=main`), copies `tests/fixtures/repos/proof-basic`, sets a local git identity,
     adds `origin`, commits and pushes. Monkeypatch `tempfile.tempdir` to `tmp_path` in the
     `write_pr` tests, as `tests/prove/test_prove.py` does.
  2. Write failing tests for the refusal order:
     - a plain directory → `NOT_A_GIT_REPO`;
     - an empty proposal → `NO_PATCH`;
     - one modified file → `DIRTY_CHECKOUT`;
     - one untracked non-ignored file → `DIRTY_CHECKOUT`;
     - an ignored file alone → proceeds to the fake;
     - no `origin` → `NO_REMOTE`;
     - `UNVERIFIED` without opt-in → `UNVERIFIED_NOT_ALLOWED` with `fake.calls == []`;
     - a fake default of `""` and no `base` → `UNKNOWN_DEFAULT_BRANCH`;
     - a fake default equal to the rendered branch → `DEFAULT_BRANCH`;
     - a fake existing branch → `BRANCH_EXISTS` and no clone/push.
  3. Run — red.
  4. Implement `write_pr`: the gate order from the spec, `render_pr`, the base resolution, the
     branch-equality check and `remote.branch_exists`; return `PrResult(REFUSED, ...)` with a capped
     `detail` where a command failed. Do not clone yet.
  5. Run — green.
- **Validation:** `uv run pytest tests/pr/test_write.py -k "refus or gate or dirty"`.
- **Commit:** `feat(pr): gate PR writing on named preconditions`

## Phase 3: Push, PR and the real adapter

- **Goal:** the branch is pushed and the PR is created through one seam.
- **Prerequisites:** Phase 2.
- **Files:** `src/tenon/pr/remote.py`, `src/tenon/pr/write.py`, `tests/pr/test_remote.py` (new),
  `tests/pr/test_write.py`.
- **Steps:**
  1. Write failing tests for `GitGhRemote` with an injected runner (a callable returning
     `subprocess.CompletedProcess`):
     - `push` builds exactly `["git", "push", "--set-upstream", "origin", branch]`, cwd=clone, env
       contains `GIT_TERMINAL_PROMPT=0`, no `--force`;
     - `create_pr` builds `["gh", "pr", "create", "--base", base, "--head", branch, "--title",
       title, "--body-file", "-"]`, adds `--draft` only when asked, passes the body as stdin, sets
       `GH_PROMPT_DISABLED=1`, and returns the last non-empty stdout line;
     - a non-zero exit, an `OSError` (missing binary) and an unparseable URL raise `RemoteError` with
       a capped detail;
     - `default_branch` parses `origin/main` from `symbolic-ref`, falls back to the
       `ref: refs/heads/main\tHEAD` line from `ls-remote --symref`, and returns `""` when both fail;
     - `branch_exists` maps exit 0 to `True`, exit 2 to `False`, anything else to `RemoteError`.
  2. Run — red.
  3. Implement `Remote` (typing `Protocol`), `RemoteError`, `GitGhRemote` and the `write_pr`
     orchestration: `push` then `create_pr`; map `RemoteError` to `PUSH_FAILED` / `PR_FAILED`; pass
     `draft = proof.level is ProofLevel.UNVERIFIED`.
  4. Run — green.
- **Validation:** `uv run pytest tests/pr/test_remote.py tests/pr/test_write.py -k "push or pr or adapter"`.
- **Commit:** `feat(pr): push a branch and open the PR through the adapter`

## Testing strategy

- `tests/pr/test_remote.py`: pure argv/env/stdout tests with a fake runner; no real processes.
- `tests/pr/test_write.py`: real `git` against temp repos and a local bare remote; no `gh`, no
  network.
- One test per acceptance criterion, cited as `# Spec AC<n>`.
- Every test asserts cleanup (`tenon-pr-*` absent) and source-tree isolation where a clone runs.

## Environment & secrets

- `git` must be on `PATH`; tests configure `user.name` and `user.email` locally in the temp repos.
- No `GH_TOKEN`, no `gh` login, no network.
- The real adapter reads no Tenon-specific environment variable; `gh` uses the user's own auth when
  invoked in production.

## Edge cases & error handling

- A temp-dir or clone failure is `COPY_FAILED`, not a traceback.
- A missing git identity is `COMMIT_FAILED` with the stderr tail.
- A push that succeeds and a PR that fails leaves the branch; `PR_FAILED` reports it and the detail
  says the branch was pushed. No remote cleanup.
- A branch created between `branch_exists` and `push` fails the push; never force.
- Submodules/LFS content may be absent in the clone; note it in the refusal detail if the apply or
  commit fails.
- `git`/`gh` must never prompt: `GIT_TERMINAL_PROMPT=0`, `GH_PROMPT_DISABLED=1`, timeouts.
