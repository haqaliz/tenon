## Phase 1: Packaging and the static token

- **Goal:** the dependencies and the simplest provider.
- **Prerequisites:** none.
- **Files:** `pyproject.toml`, `uv.lock`, `app.py`, tests.
- **Steps:**
  1. Add the optional extra and dev deps; `uv sync`; confirm the imports.
  2. Write failing tests: `StaticToken("t")` returns `t`; an empty token raises.
  3. Run — red; implement; green.
- **Validation:** `uv run pytest tests/pr/test_app_token.py -k static`.
- **Commit:** `feat(pr): package the GitHub App extra`

## Phase 2: App JWT and installation exchange

- **Goal:** an installation token from the app credentials.
- **Prerequisites:** Phase 1.
- **Files:** `app.py`, tests.
- **Steps:**
  1. Generate a test RSA key with `cryptography`; write failing tests: the JWT claims/signature/
     RS256; the exchange request URL/headers/body; a 201 token; a 401/500/invalid body is
     `RemoteError` without the JWT/token; a bad PEM is `RemoteError`.
  2. Run — red; implement; green.
- **Validation:** `uv run pytest tests/pr/test_app_token.py -k "jwt or exchange"`.
- **Commit:** `feat(pr): mint GitHub App installation tokens`

## Phase 3: The REST client

- **Goal:** one injectable JSON client with named errors.
- **Prerequisites:** Phase 2.
- **Files:** `api.py`, tests.
- **Steps:**
  1. Write failing tests: a 200 JSON returns the dict; an empty body returns `{}`; the headers
     include bearer/accept/version; a 404/500 raises `GitHubApiError` with `status` and a capped
     message; the injected transport gets the exact method/url/headers/body.
  2. Run — red; implement; green.
- **Validation:** `uv run pytest tests/pr/test_app_token.py -k api`.
- **Commit:** `feat(pr): add the GitHub REST client`

## Phase 4: Exports and the full suite

- **Goal:** the public surface and no regressions.
- **Files:** `__init__.py`, tests.
- **Steps:** export the names; add a package import test; run the full suite.
- **Validation:** `uv run pytest` (1,571 + new tests).
- **Commit:** `feat(pr): export the GitHub App auth surface`

## Testing strategy

- A generated RSA key; a fake transport; fixed `now`; no network.
- One test per acceptance criterion, cited as `# Spec AC<n>`.

## Environment & secrets

- No real app key/token; the test key is generated in the test.

## Edge cases & error handling

- A bad PEM/JSON/status is a `RemoteError` with no secret.
- The JWT window is 60 s back / 10 min forward.
- The API version header is on every request.
